# Контракт первой версии API

Первая версия предназначена для локальной демонстрации EK1. HTTP-клиент обращается к Go API на loopback; сервер работает с PostgreSQL. Сценарии очереди, принятия, переписки, заметок, закрытия и открытия проектируются отдельно.

## Вход и ошибки

Защищённые запросы содержат `Authorization: Bearer <token>`. Сессия действует восемь часов и может быть отозвана выходом. Пользователь и роль устанавливаются сервером, из тела запроса не принимаются.

JSON-запрос ограничен 32 KiB. Неизвестные поля, несовместимые типы (например число вместо строки) и лишний JSON после первого объекта отклоняются. Используется стандартный `encoding/json`: имена полей распознаются без учёта регистра; повтор ключа со строковым значением заменяет предыдущее значение (например, два `title` дают последнее строковое значение). `null` не меняет значение строкового поля; обязательные поля проверяются после декодирования. Невалидные UTF-8 байты тела отклоняются до декодирования; одиночный экранированный суррогат вроде `\ud800` декодер заменяет на `�`. Ограничения длины, непустоты и NUL проверяются после декодирования. Это принятая политика текущей версии. [Поведение декодера Go](https://pkg.go.dev/encoding/json@go1.26.1#Unmarshal).

Ошибки зарегистрированных обработчиков имеют JSON-вид `{"error":"описание"}` и не содержат SQL, пароль, токен или данные чужого обращения. Стандартный роутер возвращает `404 text/plain` для неизвестного пути и `405 text/plain` с заголовком `Allow` для неподдерживаемого метода известного пути. У реализованных маршрутов query-параметры не используются.

| Код | Значение |
| --- | --- |
| 400 | Неверное тело или номер обращения |
| 401 | Вход не подтверждён либо сессия недействительна |
| 403 | Роль не позволяет выполнить действие |
| 404 | Обращение отсутствует либо недоступно; также неизвестный путь роутера |
| 405 | Метод не поддерживается для известного пути; допустимые методы в `Allow` |
| 413 | Тело превышает предел |
| 429 | Заняты все места выполнения проверки пароля |
| 503 | База недоступна; защищённые операции не выполняются |

## Реализованные маршруты

| Метод и путь | Ввод | Результат |
| --- | --- | --- |
| `GET /health` | — | 200, `{"status":"ok"}`; подтверждает процесс |
| `GET /ready` | — | 200 при доступной БД, иначе 503 |
| `POST /login` | `login`, `password` | 200: объект с `token`, `expires_at`; пользователя возвращает `/me` |
| `GET /me` | Сессия | 200: `id`, `login`, `role` |
| `POST /logout` | Сессия | 200: `{"status":"logged out"}`; текущий токен отозван |
| `POST /tickets` | Сессия заявителя; `title`, `description` | 201: созданное обращение |
| `GET /tickets` | Сессия | 200: массив обращений; при отсутствии доступных записей `[]` |
| `GET /tickets/{id}` | Сессия; положительный номер | 200: доступное обращение |

Для входа: `login` — 1–64 байта, `password` — 1–256 байт. Создаваемый seed пароль должен быть 12–256 байт.

`title`: непустая строка до 200 Unicode-символов; `description`: непустая строка до 4000. Пробельные строки и NUL отклоняются; допустимые тексты сохраняются в том виде, который получен после описанного выше JSON-декодирования, без интерпретации SQL. Список содержит все доступные пользователю обращения в порядке убывания номера. Пагинация отложена до следующего этапа; текущая версия рассчитана на небольшой учебный набор данных.

Заявитель (`requester`) создаёт обращение от своего имени и читает только свои обращения. Специалист (`specialist`) читает только назначенные ему; новые обращения без назначения ему недоступны. Проекции свободной очереди в этой версии ещё нет.

Ответ обращения содержит только `id`, `title`, `description`, `status`, `created_at`, `version`. Поля аккаунтов, хеши паролей, сессии и будущие внутренние заметки в DTO не входят. При создании сервер устанавливает автора, состояние `new`, время и версию `1`; специалисту создание недоступно.

Примеры учебных аккаунтов: `requester_a`, `requester_b`, `specialist_1`, `specialist_2`. Пароль задаётся локально при подготовке БД; значения паролей и токенов не сохраняются в репозитории.

## Планируемые команды

Принятие нового обращения, сообщения, заметки, закрытие и повторное открытие отсутствуют в первой версии API. Их нельзя считать реализованными по одному описанию контракта. Для команд смены состояния планируются ожидаемая версия обращения, атомарная проверка/изменение и сохранение истории. Источник `expected_version`, конфликт 409 и условия отказа описаны в [D-03](DESIGN_DECISIONS.md#d-03-атомарное-назначение-версия-и-история-переходов); это контракт будущих команд.
